# FeedFlow 요구사항 정의서

배합사료 유통 관리 플랫폼의 **관리자 시스템(Admin) 및 대시보드 모듈** 요구사항과 구현 현황.

- **개발 범위**: 관리자/창고(WMS) 기능만. B2C 농가용 쇼핑몰 기능은 이 저장소의 범위가 아니다.
- **기술 스택**: Java 21 / Spring Boot 3.5.16 / Gradle / H2(in-memory) / Spring Data JPA / Thymeleaf / Bootstrap 5 / Chart.js
- **DB 명명 규칙**: 테이블·컬럼 모두 camelCase (`.kiro/steering/db-naming-convention.md` 참고)
- **ERD**: [docs/erd.md](erd.md) (Mermaid), `docs/erd-columns.tsv` · `erd-relations.tsv` · `erd-enums.tsv`

## 표기 규칙

| 표기 | 뜻 |
|---|---|
| 완료 | 기능이 구현되어 화면/API로 동작하며 단위 테스트가 있다 |
| 부분 | 도메인·서비스는 있으나 화면 또는 실행 경로가 없다 |
| 미착수 | 코드가 존재하지 않는다 |

커밋 해시는 해당 기능이 **처음 도입된** 커밋이다. 이후 수정·개선 커밋은 별도로 적지 않았다.

> 로컬 저장소는 shallow clone(depth=1) 상태라 `001d65d` 이전 이력이 없다. 초기 구축 단계에서
> 한꺼번에 들어온 기능들은 모두 `001d65d`(128개 파일)로 표기한다. 정확한 최초 커밋이 필요하면
> GitHub 저장소에서 전체 이력을 확인해야 한다.

## Epic: 전국 다중 창고 기반 물류망 확장 (P4a · P4c 완료)

WMS 1.0 은 **단일 물류센터 안에 창고 건물 2동(`WH1` · `WH2`)** 을 전제로 만들었다.
이를 **전국 여러 센터(Center)** 구조로 확장한다. 덩치가 커서 4단계로 나눈다.

| Phase | 범위 | 상태 |
|---|---|---|
| **P1** | 기초 공사 — `Warehouse` enum → `Center` 엔티티 승격, 구역(Bin) 매핑 전환 | **완료** `8f7aaf8` |
| **P2** | 검색 및 조회 — 재고·이력 조회에 센터 필터 조건 추가 | **완료** `3e77941` |
| **P3a** | 센터 간 이동 — `TRANSFER_OUT` · `TRANSFER_IN` 신설, `IN_TRANSIT` 가상 구역 | **완료** |
| P3b | 운송 중 상태 관리 — 도착 처리 분리 · 이관 전표 | 보류 (범위 초과) |
| **P4a** | 대시보드 — 센터별 재고 분포 · 실적 시각화 | **완료** |
| **P4c** | 전국 거점 지도 — `Center` 좌표 컬럼 + 2D 도면 양방향 연동 | **완료** |
| P4b | 스마트 주문 할당 — 배송지 → 센터 라우팅 | 보류 (배송지 좌표 · 권역 우선순위 부재) |

### 확정된 정책

| 항목 | 결정 | 근거 |
|---|---|---|
| **`Product.totalStock`** | **전국 합계로 유지** | B2C 쇼핑몰이 이 컬럼을 '판매 가능 수량' 으로 쓰고 있다. 센터별로 쪼개면 연동이 깨진다. 센터별 가용 재고는 **동적 쿼리 · 별도 집계**로 푼다. |
| 재고 3계층 불변식 | 유지 | `totalStock` = Σ`lotQuantity` = Σ`Inventory.quantity`. 센터가 늘어도 성립한다(전국 합계 기준). |
| 센터 간 이동에 `MOVE` 재사용 | **금지** | `MOVE` 는 sign 0(총량 불변)이지만 센터 간에는 한쪽 센터의 재고가 실제로 줄어든다. P3 에서 별도 유형을 만든다. |

### Phase 2 에서 의도적으로 미룬 것

| 항목 | 이유 |
|---|---|
| 폐기 화면(`/admin/inventory/disposal`) 센터 필터 | 폐기는 만료 재고를 **전국 단위로 훑는 것이 기본 동작**이다. 센터로 좁히는 요구가 실제로 나오면 `:centerId` 를 추가한다. N+1 만 먼저 고쳤다. |
| 입·출고 이력 목록(`/admin/inventory/movements`) 센터 필터 | 이력 목록은 품목·유형 축으로 보는 화면이다. 센터 축이 필요해지는 시점은 P4(센터별 실적)에 가깝다. |
| 센터 간 이동 **차단** | 이동 화면은 여전히 다른 센터의 구역을 고를 수 있다. 막으려면 `TRANSFER_*` 유형과 운송 중 상태가 함께 있어야 하므로 P3 에서 한 번에 처리한다. P2 에서는 **발생 시 경고로 드러나게만** 했다. |

### Phase 4c 상세 — 전국 거점 지도

2D 도면은 창고 한 동의 내부를 보여준다. 전국 5거점으로 넓혔어도 도면만으로는
그 창고가 전국에서 어디인지 드러나지 않아 탭 이름을 읽어야 알 수 있었다.

| # | 항목 | 상태 | 비고 |
|---|---|---|---|
| P4c-1 | `Center` 에 `latitude` · `longitude` 컬럼 추가 (nullable) | 완료 | 좌표는 파생값이 아닌 기준 정보 |
| P4c-2 | 5거점 좌표 시드 | 완료 | 읍 · 면 중심 기준 |
| P4c-3 | 핀 조회 API `GET /api/admin/center-pins` | 완료 | 좌표 + 재고 + 적재율을 한 응답에 (STAFF 도 조회) |
| P4c-4 | Leaflet + OSM 지도 렌더링 | 완료 | API 키 없이 동작 |
| P4c-5 | 도면 탭 → 지도 핀 강조 · 중심 이동 | 완료 | 같은 센터면 페이지 이동 없이 지도만 이동 |
| P4c-6 | 지도 핀 → 도면 전환 | 완료 | 도면은 서버 렌더링이라 `?centerId=` 로 재요청 |
| P4c-7 | 좌표 미등록 센터 수 알림 (`missingCount`) | 완료 | 조용히 빼면 핀 수 차이를 눈치채지 못한다 |

**확정된 정책**

| 항목 | 결정 | 근거 |
|---|---|---|
| 좌표 저장 위치 | **`Center` 엔티티 컬럼** | 좌표는 센터가 가진 속성이다. 프론트엔드 Geocoder 는 API 키 · 호출 한도가 있고 실패 시 핀이 0개가 된다. 기획 주소가 `"고덕면 몽곡리 667 일대"` 처럼 범위라 변환 결과가 호출마다 달라질 수 있다 |
| 좌표 `nullable` | **허용** | 부지 확정 전 센터 등록을 막지 않는다. 좌표가 없으면 지도에서만 빠지고 도면 · 재고 · 이관은 정상 동작한다. 위도만 있는 센터도 누락으로 센다 |
| 지도 라이브러리 | **Leaflet 1.9.4 + OpenStreetMap** | 카카오맵 · 네이버지도는 앱 키 발급 + 도메인 등록 없이는 지도가 아예 뜨지 않는다. 포트폴리오를 받아 실행하는 사람이 빈 화면을 보게 된다. 교체 지점은 `createMap` / `addPin` / `focusPin` 세 함수로 국소화했다 |
| 지도 데이터 전달 | **HTML 이 아니라 별도 `fetch`** | 지도는 보조 정보다. CDN · 타일 서버가 죽어도 2D 도면 본문은 그대로 보여야 한다 |
| 좌표 + 재고를 한 응답에 | 묶어서 내려준다 | 따로 요청하면 두 응답을 화면에서 다시 짝지어야 하고, 한쪽만 실패한 경우의 처리도 늘어난다 |

### Phase 4b 를 여전히 보류하는 이유

P4c 로 **센터 좌표는 확보했다.** 그래도 두 가지가 없다.

| 필요 | 현재 |
|---|---|
| ~~센터 좌표~~ | 확보 (`Center.latitude` · `longitude`) |
| 주문 배송지 좌표 | `Order.shippingAddress` 문자열뿐. 지오코딩 없이는 주소 파싱이 된다 |
| 권역 → 센터 우선순위 | 없다 |

거리만으로 정할 수도 없다. **최단 거리 센터가 그 축종을 취급하지 않을 수 있다** —
나주는 가금 전용이라 소 사료 주문을 받을 수 없다. 거리 + 취급 축종 + 가용 재고를
함께 보는 규칙이 필요하고, 좌표가 있다고 해결되는 문제가 아니다.

### 시드 데이터 밸런싱 (P4c 와 함께 처리)

정합성 규칙을 다 지켜도 **기능을 보여주지 못하는 데이터**가 만들어진다.

| 증상 | 규칙 위반 | 화면에서 보이는 것 |
|---|---|---|
| 최근 7일 입고 +1,660 / 출고 -10 | 없음 | "물류가 멈춘 창고" |
| 활성 보관 구역인데 재고 0 | 없음 | 2D 도면의 영구 빈 칸 |
| 시드 상태에서 이미 포화(80%↑) | 없음 | 재고 이동을 시연할 여유가 없다 |

조치:

| # | 항목 | 결과 |
|---|---|---|
| 1 | `SHIPPED` · `DELIVERED` 주문 10건 전부에 `OUTBOUND` 부여 | 출고 180포대 |
| 2 | 짝이 되는 `INBOUND` 를 **25일 더 오래된 날짜**로 추가 | 기간 집계는 움직이고 최종 재고 배치는 불변 |
| 3 | 로트를 적재율 낮은 구역 순으로 분할 적재 (최소 100포대) | 포화 0곳 · 활성 구역 빈칸 0곳 |
| 4 | 저온 구역을 영양제 취급 센터에만 배치 | 나주(가금 전용)의 영구 빈 구역 제거 |
| 5 | `로트 × 구역` 단위까지 이력 = 재고 일치 | 이력 추적 화면의 정합성 경고가 뜨지 않는다 |

최근 7일 **입고 +310 / 출고 -180 · 폐기 -15** 로, 대시보드 기간 카드가 한쪽으로
쏠리지 않는다.

## 검증 상태

- 단위/통합 테스트 — 테스트 메서드 **230개 선언 / 17개 테스트 클래스**
  (`@ParameterizedTest` 전개 포함 실행 시 약 236건)
- 시드 데이터(`data.sql`) 정합성 — 변경 시 함께 검증해야 한다.
  1. 이력 누적(`SUM(StockMovement × sign)`) = `ProductLot.lotQuantity`
  2. 구역 재고 합계(`SUM(Inventory.quantity)`) = `ProductLot.lotQuantity`
  3. 품목 장부(`Product.totalStock`) = 품목별 로트 수량 합계
  4. 구역별 적재량 ≤ `WarehouseBin.maxCapacity`
  5. **`로트 × 구역` 단위 이력 누적 = 해당 구역의 재고**
     — 4번까지만 지켜도 `MOVE` · `TRANSFER` 의 출발 구역에 입고 기록이 없으면
     구역별로는 어긋난다. 이력 추적 화면의 정합성 경고가 그 조건을 본다.
- 시드 데이터 **표시 품질** — 정합성만으로는 "기능을 보여줄 수 있는 데이터인지" 를 못 잡는다.
  1. 활성 보관 구역에 재고가 0인 곳이 없다 (도면의 영구 빈 칸)
  2. 시드 상태에서 이미 포화(80%↑)인 구역이 없다 (이동 시연 여유)
  3. 최근 7일 입고 · 출고가 모두 0이 아니고 한쪽으로 쏠리지 않는다
  4. 최근 30일 이력이 없는 센터가 없다
  5. 모든 활성 센터에 지도 좌표가 있고, 값이 대한민국 범위 안에 있다
- 개발 샌드박스는 외부 네트워크가 차단(`INTEGRATIONS_ONLY`)되어 Gradle 의존성을 받을 수 없다.
  **컴파일·테스트 실행은 로컬 환경에서만 가능**하며, 샌드박스에서는 정적 검사로 대체한다 —
  import 누락/미사용, 괄호 균형, enum `switch` 망라성, JPQL `select new` 인자 수 ↔ record
  컴포넌트 수, 테스트 스텁 ↔ 리포지토리 메서드 존재, 템플릿 태그 중첩, 템플릿 `${}` ↔
  컨트롤러 모델 키, 템플릿 프로퍼티 ↔ DTO 게터, JS 가 읽는 JSON 필드 ↔ record 컴포넌트,
  인라인/정적 JS 문법(`node --check`), CSS 괄호 균형.
